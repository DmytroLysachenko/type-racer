## Existing product and architecture

Next.js 16.4.0 App Router and React 19.3.0 render a static root route with a client-side race interface. The browser fetches `/api/time`, obtains a guest identity from `/api/guest`, and joins Pusher presence through `/api/pusher/auth`. There is no database, account system, Server Action, or durable shared score store. The approved `/practice` route adds server-rendered entry content and client-only timed and word-count interaction. The round is a 5-second lobby, 20-second race, and 6-second results cycle. The same bundled passage is selected by round ID. A player can change their display name; up to 50 personal results live in a versioned `localStorage` schema, with legacy race results read and migrated on the next save. `lib/game` contains pure round, input, metric, progress, and history rules; hooks manage browser lifecycle and Pusher. CSS tokens and two UI primitives are reusable without Pusher. Tests comprise Jest rules/routes/UI checks and Playwright journeys.

### Security details

No raw user text is inserted into HTML: React renders names and progress as text. The new `app/layout.tsx` inline theme script is a fixed literal with no user interpolation; its only input is checked against `light` and `dark`. Signing keys are read in server modules; only `NEXT_PUBLIC_` Pusher connection values enter the browser. Guest cookies are signed, HttpOnly, SameSite=Lax, time-limited, and Secure in production. The presence route checks the signed identity, channel window, socket format, body size, and origin when supplied. These controls protect room membership, not score truth. The app has no database queries or account authorization to audit.

`pnpm audit` advisories: [braces GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) and [sprintf-js GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c). [OWASP input validation guidance](https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html) supports bounded, allowlisted request parsing. [OWASP CSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) informs the existing origin and cookie checks.

The live two-browser Pusher check passed before the later refactor, failed once after a forced offline/online cycle when a peer was absent in the next round, and passed twice on rerun. The UI now reports a room as connected only after that room's subscription succeeds, rather than from the shared socket state alone. The intermittent peer absence is not conclusively diagnosed; provider-backed reconnection should be watched in deployment. `X-Frame-Options: DENY` now prevents framing of the application.

### UI and accessibility review

The current visual direction is compact and typing-first, with semantic tokens, visible focus, reduced-motion rules, a labeled input, a hidden accessible passage, and no per-character live announcements. The [fresh Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) review found these follow-ups:

```text
lib/game/history.ts — malformed stored metric fields reached visible history; fixed.
components/TypingArea.tsx — grapheme display and bounded composition commits have pure-rule tests; physical-device IME behavior still needs review.
components/TypingInput.tsx — native paste is available; the typing rule rejects bulk insertion, and the input help text explains that behavior. Text drop is prevented directly.
app/page.tsx — static shell now renders outside the race client island; field hydration impact remains unmeasured.
app/layout.tsx — canonical metadata requires a configured production `SITE_URL`.
```

Automated axe checks pass on desktop/mobile Chromium, light/dark, practice, and results; that does not prove WCAG 2.2 AA. A 320-pixel viewport with the root text size doubled exposed horizontal overflow in the header and practice timer; both now wrap, and a browser regression test covers both routes. A basic Tab-order check reached the skip link, navigation, theme, and typing controls in a sensible order. The reflow check simulates enlarged text, not browser zoom or a screen reader. Manual screen-reader, complete keyboard-only, browser-zoom, and real touch-device review remain. WCAG 2.2 AA's [target-size criterion](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) is 24 CSS pixels or adequate spacing; this app uses 44-pixel controls as a stronger usability target.

## Research and product implications

Public pages were accessible for [Monkeytype](https://monkeytype.com/about), [TypeRacer](https://play.typeracer.com/), [TypingClub](https://www.typingclub.com/), and [10FastFingers](https://10fastfingers.com/). Keybr's landing page returned no useful page text through the research tool, so no claim about its current interface is made. Verified public patterns: Monkeytype presents multiple test modes and detailed personal settings; TypeRacer offers multiplayer, solo practice, and accounts for saved races; TypingClub emphasizes lessons and progress; 10FastFingers offers tests and competitions. The inference for TypeArena is to preserve a short shared-race identity and add useful personal practice separately, without copying their designs or importing copyrighted passages. The UI skill's database suggested an oversized review-page layout and green gaming palette; those recommendations conflict with this product's focused race and the user's calm direction, so they were rejected.

Official guidance consulted: [Next.js server/client rendering](https://nextjs.org/docs/app/getting-started/server-and-client-components), [React state ownership](https://react.dev/learn/preserving-and-resetting-state), [web.dev measurement guidance](https://web.dev/articles/vitals-measurement-getting-started), [Vercel package-manager behavior](https://vercel.com/docs/package-managers), and the sources above. All cross-product recommendations in this report are inferences, not copied implementations.

## Follow-up implementation and verification — 2026-10-17

After the initial audit, the owner asked to implement remaining local plan items. Practice now includes original short thoughts, number/punctuation, gentle/challenge and Polish material plus private custom text. The app remembers the last mode, offers validated JSON export and deletion of both history formats, records bounded counts of missed target characters, and gives measured practice suggestions and a passage retry. Custom text is never saved or transmitted. The race footer and mobile practice clock were adjusted after a repeatable throttled probe found layout shifts; see [performance.md](performance.md).

Pusher now requests peer snapshots on subscription and twice more over three seconds, addressing a race between peers reconnecting. Three successive configured two-browser tests passed against the local production server, including forced offline/online, snapshot recovery, results and rollover. This is evidence of local provider-backed recovery, not a deployed guarantee. The current code passed a production build, 58 Jest tests in 15 suites, the game-rule coverage gate, lint, TypeScript, formatting, a frozen pnpm install, and 34 credential-free desktop/mobile browser flows; two opt-in live cases were skipped in the ordinary browser run. The earlier hosted CI run for revision `a429711` passed, but the current uncommitted revision has no hosted run or deployment check.

A fresh `pnpm audit --prod` reported zero known production advisories. Full `pnpm audit` still reported a development-only high advisory in `braces` and a moderate one in `sprintf-js`; the advised patched versions were not published in the registry when checked. Real-device IME, screen-reader, browser zoom and production environment validation remain open; automated axe and simulated reflow cannot certify WCAG 2.2 AA.

The subsequent release-readiness pass restored native paste events in the shared typing input while keeping bulk insertion rejected by the game rules. It also added a production dependency audit to GitHub Actions and removed global smooth scrolling after Next.js reported it during browser navigation. The local audit gate found zero production advisories; the updated hosted workflow has not yet run. A new `verify:deployment` command passed locally with `SITE_URL` configured and checks page headings, canonical URLs, robots/sitemap, server time and guest-cookie flags. It cannot establish live presence or physical-device accessibility.
