# Modernization roadmap

Each item describes current state, change, benefit, affected area, and proof. Checkmarks are updated only after verification.

## Phase B: foundation

- [x] **P0 Fix and contain untrusted server scores.** Current `/api/finish` corrupts in-memory aggregates and trusts submitted scores. Validate or retire score writes and remove public raw player output. This prevents false results/data exposure. Areas: `app/api/finish`, `lib/store`, `app/players`, Pusher auth. Verify the score route and raw player page are absent and auth route tests cover unavailable service, invalid requests and valid presence. Depends on the guest trust decision.
- [x] **P0 Keep the multiplayer app usable when Pusher is unavailable.** Current client/server constructors assume secrets. Guard live service and show its status while retaining presence when configured. Areas: `lib/pusher.*`, API routes, page/table. Verify browser fallback and two-browser configured presence.
- [x] **P1 Repair tooling and dependency health.** Current Jest is blocked, Next is pinned to a vulnerable patch, `next lint` is deprecated, and two lockfiles exist. Choose pnpm, upgrade compatible stable dependencies, restore tests, add typecheck/format/CI, tighten lint. Areas: package/config/lockfiles/workflow. Verify install, audit, lint, tests, typecheck, build. Depends on no application changes.
- [x] **P1 Clarify module ownership.** Hooks currently mix game rules, network, state and rendering. Move pure metrics/session logic into `lib/game`, keep hooks as adapters, avoid unnecessary layers. Verify pure unit tests and unchanged browser flow. Areas: hooks, metrics, components.

## Phase C: core game

- [x] **P0 Correct typing formulas and input.** Current whole-word WPM and unrestricted edits produce misleading scores. Use Unicode code points, five-character raw/net WPM, CPM, accuracy and mistake accounting with stable zero-time behavior; constrain append/backspace input and reject paste. Areas: game module, hook, typing component. Verify focused edge tests (Unicode, punctuation, rapid input, repeated mistakes, corrections, completion).
- [x] **P1 Make shared race lifecycle explicit.** Current 20 second shared round can end instantly and has no results snapshot. Keep the shared wall-clock passage, countdown and presence room; introduce ready/running/completed states, monotonic typing elapsed time, visibility handling, automatic next-round reset and a result view. Areas: round hook, game hook, page, typing panel, Pusher client. Verify transition tests, E2E rollover, and two-browser presence/progress/rollover.
- [x] **P1 Persist guest history safely.** Current player parsing may crash and process-memory stats vanish. Validate local identity and store bounded personal race history locally; label it as device-only. Areas: player hook, new storage utility, results/profile. Verify corrupt history storage, restart and persisted history tests; guest identity is covered in browser tests. Depends on stable metrics.

## Phase D: experience

- [x] **P2 Refresh the UI.** Current UI is sparse and lacks results/focus hierarchy. Add design tokens, clear typing area/caret, stats, results/history, responsive panels, reduced motion and dark/light theme. Areas: `app/globals.css`, page/components. Verify keyboard and mobile viewport flows. Depends on lifecycle.
- [x] **P2 Improve accessibility and metadata.** Current labels and focus are incomplete and metadata generic. Add semantic landmarks, labels, focus states, contrast, live announcements, title/description/Open Graph, robots for private pages. Areas: layout, page, components, robots. Verify accessibility inspection and browser tests. Depends on UI.
- [x] **P2 Expand meaningful tests.** Baseline lacks input, lifecycle, persistence and API cases. Test public behavior with Jest/Testing Library and a critical Playwright flow. Areas: `__tests__`, `e2e`. Verify suite, coverage report and desktop/mobile Chromium flows. Depends on implementation.

## Phase E: polish

- [x] **P3 Trim measured performance issues.** Current duplicate timers and work per key may add latency. Consolidate timers and avoid needless rerenders; record a local production-load measurement. Verify build output and browser typing responsiveness. Depends on core game/UI.
- [x] **P3 Complete developer handoff.** README is challenge-specific and environment instructions are incomplete. Add `.env.example`, scripts, CI, architecture/testing/decision docs and final commit guide. Verify commands from a clean install as far as local environment allows. Depends on final implementation.

Optional features (daily challenge, achievements, languages, verified global leaderboard) are deferred. Multiplayer is the core product. A verified leaderboard requires new trusted infrastructure and must not use Pusher client events as proof of scores.

## Multiplayer production pass (2026-10-11)

- [x] **P0 Synchronize rounds to server time.** The browser currently chooses its own epoch round, so device clock skew separates players. Add a no-store server clock sample, monotonic client projection and resync on visibility/reconnection. Model a shared lobby, active race and results interval. Areas: `lib/game/rounds`, `useRound`, time route, Pusher authorization, page. Verify deterministic phase tests and two-browser synchronization. Depends on preserving the existing presence channel contract.
- [x] **P1 Make results a shared phase.** The table currently disappears at rollover and has no stable ranking. Keep the room through a results interval, show ordered finishers and local result feedback, then advance together. Areas: `TypingArea`, `ScoreTable`, Pusher payloads, styles. Verify phase and two-browser result tests. Depends on round phases.
- [x] **P1 Recover from disconnects.** Pusher subscriptions currently hide connection failures and returning visitors miss peers' latest progress. Expose connection status, request/resend snapshots after subscription, and clear stale presence state on reconnect. Areas: Pusher client and room UI. Verify reconnection and stale-state tests. Depends on stable round ownership.
- [x] **P0 Contain score abuse honestly.** Client-supplied progress is forgeable. Validate all received fields and ranges, calculate display metrics from bounded data where possible, avoid storing or advertising unverified competitive rankings, and document requirements for authoritative scores. Areas: progress module, auth route, room UI, docs. Verify malformed/spoofed payload tests. A truly verified leaderboard still depends on server-observed typing events, durable shared storage and a stronger identity policy than signed guest cookies.
- [x] **P2 Exercise multiplayer in two browsers.** Credential-free UI tests cannot prove Pusher delivery. Add an opt-in two-context suite for a configured Pusher app and keep deterministic phase/UI tests in ordinary CI. Areas: Playwright config/tests and test docs. Verify both modes locally. Depends on the protocol and UI changes.

## Production gates beyond the local social-racing release

- [x] **P0 Reject stale peer state and bound server requests.** Pusher events can arrive late, a rejoining member can erase progress, a browser can replay a signed cookie forever, and request bodies can omit `Content-Length`. Accept only monotonic peer snapshots, preserve progress on presence rejoin, expire signed sessions, cap streamed bodies, reject duplicate authorization fields and cross-origin authorization. Areas: `lib/game/progress`, `ScoreTable`, guest/auth routes, `lib/guest-session`, `lib/http`. Verify focused tests and the configured two-browser suite. Depends on existing presence identity.
- [x] **P2 Complete the web interaction audit.** The race blocked browser paste and animated progress width; small landscape and reduced-motion behavior lacked checks. Let ordinary paste events through while the race rule rejects bulk input, animate progress with transform, strengthen focus/touch/hover states and test small landscape. Areas: typing/profile/page/styles/E2E. Verify axe and browser tests against the [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines). Depends on current UI.
- [ ] **P0 Add authoritative, durable competitive results if public rankings are required.** Current standings are client-sent social feedback and history is browser-local. A competitive result needs server-observed ordered input, per-round replay protection, an atomic shared store, retention limits and an identity/abuse policy. Areas: new server race module, server routes, distributed store, room results UI and integration tests. Verify cross-instance concurrent submissions, disconnect/retry, scoring, expiry and abuse limits against a provisioned test store. Depends on a selected/provisioned shared datastore and product decision on guest versus account identity. Do not label the existing client event as verified.
- [ ] **P0 Validate the deployed Vercel environment before calling the release fully production-verified.** Local and configured two-browser tests pass, but the deployed instance has not been checked with the updated code or its environment settings. Verify deployment configuration, HTTPS cookie behavior, live two-device room, reconnect and logs using the owner's release process. Areas: deployment/environment only. Depends on owner-controlled deployment and credentials; pushing `main` may trigger Vercel automatically, but no direct deployment or infrastructure change was performed here.

## Reusable architecture and developer workflow pass

- [x] **P1 Give the live room a clear module seam.** `ScoreTable` owned Pusher subscriptions, presence reconciliation, local event listening and markup. Subscription/state logic now lives in `useRoomStandings`; the table renders its output. Existing component tests and the live two-browser flow pass. Areas: `components/ScoreTable`, `lib/hooks`, standings tests. Depends on existing validated progress module.
- [x] **P1 Make local progress an explicit data flow.** Typing and standings previously exchanged local progress through a window event, and keying the whole page's main content to a round reset unsaved profile input. `RaceRound` now owns one keyed typing session and passes its progress to both views; the profile remains mounted across rounds. Areas: `app/page.tsx`, `components/RaceRound.tsx`, `components/TypingArea.tsx`, `components/ScoreTable.tsx`, `lib/hooks/useTypingProgress.ts`, `lib/hooks/useRoomStandings.ts`, profile E2E. Verify peer delivery with live Pusher and profile draft survival across rollover. Depends on the standings seam.
- [x] **P1 Extract portable design tokens and useful UI primitives.** Spacing, radius, shadows, form styles and button states were hardcoded in the application stylesheet. Tokens now live in a framework-independent CSS file; shared accessible button/field modules are used across race, profile and error views and documented for reuse. Dark/light browser and axe checks, focused/loading tests, responsive E2E and build pass. Areas: styles, UI modules, profile, error screen, typing input, docs. Depends on preserving race input behavior.
- [x] **P2 Strengthen CI without adding deployment.** The workflow already ran lint, typecheck, tests, build and browser checks, but did not gate coverage or define least-privilege permissions/concurrency. CI now runs `test:coverage` with an 80%+ game-rule floor, credential-free browser checks, read-only permissions and run cancellation. Local configuration and checks pass; inspect the GitHub-hosted run for the pushed revision separately. Areas: package, Jest config, GitHub workflow, README. Depends on stable test suite.
